How SET Loop was developed

Built from the work. Tested against the work.

SET Loop began with real store-execution friction: the information needed for a floorset already existed, but it lived across separate maps, files, assets, systems, and partner handoffs. Keith translated that work into a repeatable store-to-guide operating loop and tested it against actual outputs.

Straight answer

Who built SET Loop?

Keith built SET Loop from direct operating work, real map and Brand Guide production, and iterative testing against actual outputs. AI-assisted technical work helped organize requirements, compare approaches, troubleshoot, draft, and automate. Keith defined the operating model, made the decisions, validated the outputs, and retained ownership.
Verified in this build

Local and manifest-scoped

  • RC12_9, JSX/JSXBIN, InDesign files, maps, prototypes, and store work are outside the managed payload.
  • Manifest-managed regular files are backed up before replacement.
  • Browser-safe files and folders use normal relative links. Commands and native authoring files remain Finder-only and are shown by exact filename with a browse-location link.
  • No writeback to company/source systems, source-file deletion, or business action for publishing, messaging, payroll, scheduling, or approval exists. Disclosed local writes include indexes, logs, backups, sidecars, browser-local state, and user-requested exports.
Must be confirmed internally

Retention and enterprise protection

This POC cannot promise that an uploaded file is erased everywhere after 30 days, removed from backups or logs, excluded from model training, or unavailable to downstream systems. Those statements require written confirmation from Security, Privacy/Legal, the enterprise tenant owner, and the applicable vendor terms.

Working rule

Minimum necessary data

Use approved enterprise accounts, working copies instead of authority files, and only the minimum information required for the test. Do not place restricted customer, employee, payment, credential, medical, or investigation data in this local proof.

One-line policy boundary check

Ask for a policy conflict—not a prediction of punishment.

Paste the proposed action and the exact policy into the approved corporate assistant. The result can flag a boundary or missing approval; it cannot decide discipline.

Separate project-close task: clean up company files uploaded through AI chats.

This cleanup applies only to company Excel/CSV workbooks, PDFs, and images uploaded through project chats. Inventory them, place one verified recovery copy in a company-approved location, remove the local working copies, and use the platform’s available controls to remove the uploads or associated chats. It does not authorize deletion of official company sources, RC12_9, maps, InDesign files, or final deliverables—and it does not prove deletion from vendor backups, logs, caches, legal holds, or downstream systems.
