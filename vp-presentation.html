The concept

SET and SET Loop — what they are and how they connect

Two complementary systems. One governed operating model, designed to reuse approved Microsoft 365 capabilities after entitlement, policy, and ownership confirmation.

SET — Store Execution Toolkit

The build side.

SET is the proposed build side for Home Office to configure and publish store releases — floorsets, promotions, brand guides, and communications. The working prototype shows where direction can be created and governed before it reaches the field.

  • Partner intake from cross-functional teams (Visual, Merch, Marketing, Supply Chain)
  • Asset normalization and brand standard alignment
  • Floorset Factory — store-specific build with exact fixture + zone data
  • Live mapping of approved assets into fixture connector zones
  • Approval workflow before anything reaches a store
  • Publishing queue with expiration and compliance controls
SET Loop — The Field Return Path

The receive + return side.

SET Loop is what the field sees and uses. Every store, district, and region gets a role-specific hub showing exactly their content — checklists, promotions, communications, and assortment. And questions, exceptions, and evidence loop back to accountable owners.

  • Store view: floorset direction, open-to-close checklist, promos, announcements
  • District view: store readiness, support flags, escalation tracking
  • Regional view: pattern detection, repeating issues, fleet health
  • Home Office view: publishing queue, approvals, field intelligence
  • MSI / MicroStrategy dossier link — inventory and assortment by store
  • Questions route to named owners; an approved production flow can add the audit trail

Enterprise security

Designed for infrastructure you already govern

The production target is the governed Microsoft environment VS&Co already manages. The current public prototype demonstrates the experience only; identity, permissions, retention, flows, and data connections require IT and product-owner approval.

🔐 Target: Microsoft identity

Production can use VS&Co authentication after the app, site, user population, and device-access path are approved.

🏢 Target: SharePoint permissions

Role-based views can inherit approved SharePoint access, but list design and row/item-level boundaries must be validated before rollout.

🔒 Target: governed tenant storage

Production content can remain in approved Microsoft repositories. This GitHub Pages prototype is public and must not hold sensitive production data.

📋 Target: workflow audit trail

Approved Power Automate flows can log submissions, approvals, and routing after environment, connector, DLP, and run-owner confirmation.

🌐 MicroStrategy dossier preserved

Your existing MSI dossier (vsedwmsi.cloud.microstrategy.com) controls authentication, permissions, and data visibility. SET Loop adds role-specific pages — it doesn't replace your analytics.

⚡ Consolidation opportunity

A measured pilot can identify duplicated handoffs and external-tool exposure. Any replacement decision follows capability, security, ownership, and cost validation.
