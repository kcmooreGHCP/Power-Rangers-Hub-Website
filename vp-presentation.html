The real cost of the current model

What's breaking down — and why it matters

Releases are working. But information quality erodes every time it passes through an external system or gets delivered generically to the field.

⏱️

1–2 weeks to build one release

From the ops walk through to field delivery, a single floorset takes 1–2 weeks. That's before questions, corrections, and exceptions — which restart the clock.

Time cost
📡

3rd-party apps that cost and limit

Every external tool — Smartsheet, external PDFs, email chains — creates a licensing cost, a security surface, and a translation layer where context is lost.

Platform risk
🗺️

Generic releases for unique stores

Store 1392 (Ontario Mills) and Store 111 (Holyoke Mall) are structurally different. Today, both receive the same guide. Adjustments happen manually — by the store.

Quality cost
❓

Questions go to email — and wait

When a Store Manager needs clarity on a fixture, promo, or inventory qualifier, it goes to email. There is no audit trail, no routing logic, no response SLA.

Field intelligence lost
📊

RM feedback arrives weekly — too late

Regional Managers capture field patterns through weekly reports. By the time leadership sees a repeating issue, multiple releases have already been impacted.

Signal latency
🔗

Inventory, tiering, qualifiers disconnected

Field teams need to cross-reference multiple sources to understand what qualifies a fixture, what's in stock, and what the translation rules are. Each source is separate.

Integration gap

Enterprise security

Built on infrastructure you already control

This is not a new platform. SET + SET Loop uses SharePoint, Power Automate, and Microsoft 365 — the same governed infrastructure your organization already manages, audits, and secures.

🔐 Single Sign-On via Microsoft 365

Every user authenticates through the same VS&Co Microsoft identity. No separate login, no 3rd-party credentials, no credential management overhead.

🏢 Permission inheritance from SharePoint

Role-based access controls inherit from your existing SharePoint permission structure. A Store Manager only sees their store's data — automatically, without custom code.

🔒 No data leaves VS&Co infrastructure

All data — releases, assets, store structures, questions, approvals — stays inside your Microsoft tenant. No 3rd-party storage, no external API dependencies for core data.

📋 Full audit trail via Power Automate

Every approval, every change, every question and response is logged automatically. Compliance, governance, and incident investigation have a complete record — without manual tracking.

🌐 MicroStrategy dossier preserved

Your existing MicroStrategy dossier (vsedwmsi.cloud.microstrategy.com) controls authentication, permissions, calculations, and data visibility. SET Loop adds role-specific pages — it doesn't replace your analytics infrastructure.

⚡ Replaces external tool risk

Every Smartsheet link, external PDF host, or 3rd-party portal replaced by SET Loop is a security surface eliminated. Fewer tools = smaller attack surface = lower compliance burden.

Pilot plan

5 stores. 1 cycle. 14 days to proof.

We're not asking for a full rollout. We're asking for permission to prove it works with 5 pilot stores over one release cycle.

1

Week 1: Platform setup (Days 1–7)

Create SharePoint lists (Cycles, Stores, Changes, Questions, Approvals). Build Power Automate flows. Create 4 role hub pages. Connect SET HTML to SharePoint data.

2

Week 2: Pilot store onboarding (Days 8–10)

Onboard 5 stores (mix of tiers, regions). Load store-specific floorset data. Configure store-level permissions. Train Store Managers (30-min quickstart).

3

Week 2: Live cycle test (Days 10–14)

Run one real release cycle through SET + SET Loop. Measure: time to find floorset, questions submitted, response time, rework needed. Collect store feedback.

4

End of Week 2: Results & decision

Present results to leadership: time saved, quality improvement, field feedback. Decision: expand to all 798 stores or adjust and re-pilot.

What we're asking for

  • 5 volunteer pilot stores (we'll select the right mix)
  • Permission to create pages on the Co-Pilot Power Rangers Hub SharePoint site
  • Access to Power Automate for flow creation (standard M365 license)
  • 14 days to prove it works with real data
  • One release cycle to measure against current baseline
No new budget required. Everything runs on M365 licenses already owned. The only investment is time — 14 days of focused pilot work.
